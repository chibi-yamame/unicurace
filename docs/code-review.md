## 2. 設計上の問題

### D1. ゲームルールの重複（重要度: 中）
「止まるまで滑る」移動ルールとクリア判定が 4 か所に別実装されている。

- `generator.js`（生成時の移動距離計算）
- `solver.js` `slideInDirection`
- `index.html` `executeMove`（移動先計算）と `checkDeadlock`（隣接マスの判定）
- クリア判定（`checkClear` と `checkDeadlock` 内で同じ処理が 2 回）

ルールを変えると全箇所の修正が必要で、生成とゲームの挙動がずれるとクリア可能性の保証が崩れる。
→ **純粋関数のゲームルールモジュール**（例: `src/core/rules.js` の `slide(board, painted, pos, dir)`、`isCleared`、`hasAnyMove`）に集約し、生成・ソルバー・UI すべてから使う。

### D2. `index.html` への集中（重要度: 中）
約 650 行のインラインスクリプトに、状態管理・画面遷移・入力・アニメーション・タイマー・ゲーム進行がすべて同居し、グローバルな可変状態 `state` を各所で直接書き換えている。
- ブラウザなしでテストできない
- 画面遷移の前提（タイマー停止、アニメーション停止）が各ボタンのハンドラに分散し、B6・B7 のような漏れが起きやすい

→ 以下に分離する:
- `src/game/session.js`: ゲーム進行（ステージ番号、ペナルティ、統計、クリア/詰み判定）。DOM 非依存の状態機械。
- `src/game/timer.js`: 経過時間とペナルティの計算、表示用フォーマット。
- `src/ui/screens.js`: 画面遷移。遷移時に「タイマー停止・アニメーション中断」を一元的に行う。
- `src/ui/input.js`: スワイプ / マウス（＋キーボード）を方向イベントに変換。
- `src/view/animator.js`: 移動アニメーション。**論理状態（塗り）は移動開始時に確定**させ、アニメーションは見た目だけにする（B1 の根本対策）。

### D3. 生成器の責務混在（重要度: 低）
- 生成ロジックにデバッグ用ログ（日本語の方向名を含む）が混在している。ログはオプション化するか、インスペクター側で手順から復元する。
- 返り値の `painted` はブロックも `true` になっており意味が曖昧（インスペクターはこれを「塗りつぶし済み」として描画）。
- `generateStageViaSimulationWithRetry` の既定値（0.2〜0.5）がゲームの設定（0.15〜0.35）と異なる。
- `retryCount` は「最良結果を得た試行番号」で、実際の試行回数ではない。
- `getWallConstrainedDirections` の意図（壁際スタート時に最初の 1 手を壁沿いに限定）がコードからも資料からも読み取れない。
- ブロック配置時の範囲チェックは常に真（`choosenDist < maxDist` なら必ず盤内）で不要。`choosenDist` は typo。

### D4. ソルバー（重要度: 低）
- 深さ上限 1000 は意味がない（手数はマス数以下）。
- 全塗り判定を毎ノード O(N²) で走査している。塗ったマス数のカウンタで O(1) にできる。
- `N` と `grid` を内側の関数に引数で渡し直しており、外側の変数を隠している。

### D5. 設定値と仕様の管理（重要度: 低）
- `CONFIG` が `index.html` にあり、`moveRangeMax` は `gridSize - 1` が生成呼び出しに直書きされている。
- レンダラーが盤面サイズを `stageData.grid` ではなく `CONFIG.gridSize` から取っており、盤面と設定がずれると描画が壊れる。
- `findSolutionPath` の import、`solvable`・`gridX`・`gridY`・`diff` などの未使用コードが残っている。
- タイマー表示は `Date` のメソッドと手計算が混在している（分は手計算、秒とミリ秒は `Date`）。

### D6. 開発基盤（重要度: 中）
- テストがない。コアロジック（生成・ソルバー・ルール）は DOM 非依存なので、Node 標準の `node:test` でテストできる（外部依存なし）。
  - 例: 「全シードで生成経路を再生してクリアできる」「同一シード → 同一盤面」「ブロック率が範囲内」
- `package.json`・lint・formatter がない。最低限 `package.json`（`"type": "module"` とテストスクリプト）を置く。

### D7. 表示・UX（重要度: 低）
- Canvas が `devicePixelRatio` に対応しておらず、高解像度画面でぼやける。
- `height: 100vh` はスマホのアドレスバーで高さがずれる（`100dvh` 推奨）。
- PC 向けのキーボード操作（矢印キー）がない。

## 3. 推奨する進め方

各ステップで動作が変わらないこと（またはバグ修正のみ）を確認しながら進める。

1. **テスト基盤**: `package.json` と `node:test` によるコアロジックのテストを追加（現行挙動の固定）。
2. **ルールの集約（D1）**: `src/core/rules.js` を作り、生成・ソルバー・ゲームから使う。
3. **不具合修正**: B1（塗りを移動開始時に確定）、B2、B3（シード入力の検証）、B4（`moveRangeMax` 引数の廃止または検証）、B6〜B8。
4. **`index.html` の分割（D2）**: ゲーム進行を DOM 非依存のモジュールに切り出し、画面遷移時の後始末を一元化。
5. **生成方式の変更**: `stage-generation-proposals.md` の推奨方針（ステージごとの独立 PRNG、案 C、上限付き探索）。既存シードの盤面が変わるため、他の変更と分けて行う。
